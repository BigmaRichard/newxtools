# 本地前台使用说明（浏览器查看 XTools 镜像数据）

麦可旺志 Microwants · xtools 优化项目 · 2026-09-18

## 1. 是什么

一个只在本机运行的网页前台：读取 P0 只读镜像 `data/xtools_mirror.sqlite`，在浏览器里查看经营总览、订单、客户、应收与回款、工作日志，以及 0.5 起新增的销售分析、客户分析、产品与库存、采购与付款、业务员看板、联系人查询，各列表可导出 Excel。它不连接 CRM，也不向镜像库写入；数据随同步任务每 30 分钟更新一次，页面右上角显示“数据截至”时间。

只监听 `127.0.0.1`，只有这台 Mac 上的浏览器能打开；同事需要看时另行部署（见第 6 节）。

## 2. 安装与打开

首次安装为常驻服务（退出或重启登录后由 launchd 自动拉起），然后在浏览器打开：

```
cd ~/newxtools && .venv/bin/python scripts/install_launchd.py --web && sleep 3 && open http://127.0.0.1:8790
```

服务启动时会检查镜像库结构并补建查询索引（0.4 起，约 1 秒；若同步任务正在写库会先等待其提交）。日常直接打开 http://127.0.0.1:8790 即可；可以在浏览器里加为书签或“添加到程序坞”。

**放到桌面 / 程序坞**：Safari 打开 http://127.0.0.1:8790 后，用「文件 → 添加到程序坞」可以做成独立窗口的应用（有图标、无地址栏，启动台里也能搜到）；想在桌面放一个双击打开的图标，执行：

```
printf '<?xml version="1.0" encoding="UTF-8"?>\n<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">\n<plist version="1.0"><dict><key>URL</key><string>http://127.0.0.1:8790</string></dict></plist>\n' > ~/Desktop/XTools数据前台.webloc
```

| 目的 | 命令 |
|---|---|
| 临时在终端前台运行（调试） | `cd ~/newxtools && .venv/bin/python scripts/web.py` |
| 换端口 | `cd ~/newxtools && .venv/bin/python scripts/install_launchd.py --web --port 8800` |
| 卸载常驻服务 | `cd ~/newxtools && .venv/bin/python scripts/install_launchd.py --web --uninstall` |
| 查看服务状态 | `launchctl list \| grep xtools-web` |

日志：`logs/web.log`（接口耗时、错误）、`logs/launchd.web.out.log` / `launchd.web.err.log`。

| 联系人查询（0.5） | 跨客户按姓名 / 手机 / 微信 / 邮箱 / 客户名搜索，按所有者、职务筛选，“只看无联系方式”；最近联系与日志条数取挂在此联系人上的行动记录；按所有者统计缺联系方式人数 | 与第 6 节的专项报表互补：这里是已建档联系人，报表是日志里提到但未建档或无联系方式的人 |

## 4. 数据口径

| 项 | 口径 |
|---|---|
| 订单金额 | contract.sum；币种非 RMB 时在金额旁标注币种，汇总时未折算 |
| 订单关联客户 | cu_sn 为 "[id:N]" 或客户编号 sn；出库单 cu_sn 为纯数字客户 id |
| 已回款 | 回款记录（gathering_note）按 co_id = 订单 id（或订单编号）汇总 |
| 应收 | 计划回款（gathering）状态为“未回”或“部分回款”的计划金额；逾期 = 计划日期早于今天 |
| 人员 | 订单 / 回款记录的 who 为姓名；客户所有者、计划回款、出库单的 who 为 part，行动记录 who 为 ",M1,M2," 形式；均按人员表（crm_user）换算为姓名；离职人员姓名带“(离职)” |
| 同比 | 今年 1 月 1 日至今天，与上年同一区间比较 |
| 其他字段 | 详情页“其他字段”列出原始 JSON 中未进规范化表的非空字段（如自定义字段 j1…），名称取自 CRM 字段中文名 |
| 销售分析金额 | 按业务员 / 客户 / 地区 / 类型 / 月份维度用订单金额（contract.sum，外币按 money_rate 折算）；按产品 / 分类 / 大类维度或带产品条件时用订单明细金额（contract_goods.sum）与数量，明细合计与订单金额可能因税、折扣有差异 |
| 型号与批号 | 产品表的 name 为产品型号（如 SP-100-8-C4-NP），sn 为“生产批号-包装规格”（如 260227AB-20kg/桶），同一型号可有多条批号记录。**编号里的 20kg/桶 是包装规格，不是计量单位**：色谱填料的库存一律按公斤记，前台把包装规格单列一列显示。“按型号合计”按 name 分组：库存合计为各批号库存相加，销售额 / 数量 / 单数 / 客户数按该型号下所有批号的订单明细合并去重统计 |
| 计量单位 | 取自产品表的 unit。CRM 未填单位时，填料 / 介质 / 凝胶 / 树脂类按公斤显示并标星号（如 12 公斤*）。“单位不一”只在**有库存的批号之间**单位不同时才提示——早年不少批号把“桶 / 克”当成单位记，但这些记录库存均为 0，不影响合计 |
| 产品引用 | 订单明细、采购明细里的产品为编号 sn；产品没有编号时为 "[id:N]"，前台统一按产品 id 关联（出库明细按 pid）。产品表的 class 存分类标题，按 CRM 产品类别树（csstree）归到根下一级“大类” |
| 地区 | 客户表 state 为 XTools 内部省份代码；字典 customer.state 抓到后按字典显示，否则按该代码下最常见的城市 / 区推断省份，推断不出的显示“地区 N” |
| 采购 / 付款金额 | money_type 非 RMB 时按单据 money_rate（每 100 外币的人民币价）折算：人民币 = money × money_rate / 100；列表同时显示原币与折算值，汇总按折算值。个别 JPY 单据汇率记为 0.71，折算值明显偏低，属 CRM 原始数据 |
| 供应商 | 正式公司采购单的 cu_sn 均为 [id:0]，供应商取原始记录的 cu_id（0.5 起进入规范化表；已有数据需 `sync.py --rebuild --table purchase` 重建一次） |
| 付款计划状态 | pay_plan.status 0 未付 / 1 已付（字典抓到后以字典为准）；逾期 = 未付且计划日期早于今天。采购单 status 为入库状态：0 待入库 / 1 生成入库单 / 2 部分入库 / 3 全部入库（字典抓到后以字典为准） |
| 客户分析 | 客户 = 订单解析出的客户 id；“新客户”= 首单（不含意外中止）在本年；留存率 = 上年有单客户中本年也有单的比例；复购率 = 本年有单客户中 ≥2 单的比例；流失预警按最近一单距今天数分档 |
| 订单自定义字段 | 正式公司启用的 j 字段（发票类型 j7、付款方式 j8、货期 j9、是否试用 j21、首单签约 j26、提成方案 j33 等）在 CRM 里存选项代码；`sync.py --dict` 抓取选项字典后，订单列表 / 详情显示中文并可按发票类型、付款方式、货期筛选；未抓到字典的字段在详情里显示原始代码并标“（代码）”。j7 / j8 / j9 / j21 / j26 / j33 进入规范化表（已有数据需 `sync.py --rebuild --table contract`） |
| 工作日志粒度 | 一行 = CRM 中的一条行动记录。CRM 每条记录只挂一个客户和一个联系人，一天拜访几个客户、每个客户分别写一条，就显示为几行；把一次拜访中见到的几个人写进同一条，就显示为一行。前台在“联系人”下方另列出正文里提到的该客户其他已建档联系人（按 CRM 联系人表匹配，未建档的人名识别不出）。CRM 的标题字段截断为 128 字，长记录的标题只是正文开头，前台不重复显示 |

## 6. 专项报表：工作日志里缺少联系方式的联系人

`scripts/report_missing_contacts.py` 扫描近 N 年（缺省 5 年）的行动记录，抽取正文里提到的人名，对照 CRM 联系人表，找出没有联系方式的人，生成一份自包含的 HTML（`reports/联系人缺失_工作日志_近5年_日期.html`，可直接用浏览器打开，含类型 / 记录人 / 年份筛选、关键词搜索、按联系人汇总、导出 CSV）。

```
cd ~/newxtools && .venv/bin/pip install -q jieba && .venv/bin/python scripts/report_missing_contacts.py --jieba && open reports/
```

| 类型 | 含义 |
|---|---|
| 未建档（全名） | 正文里出现姓 + 名，该客户的联系人表里没有这个人；其他客户下有同名联系人时会注明 |
| 未建档（仅姓氏） | 正文只写了“彭老师”“李总”，该客户下没有这个姓的联系人 |
| 已建档无联系方式 | 对上了联系人表里的人（按全名，或姓氏只对应一人），但手机、电话、微信、QQ、邮箱都是空的 |
| 关联联系人无联系方式 | 这条日志在 CRM 里挂的联系人本身没有任何联系方式 |

人名靠规则抽取（姓名 + 称谓、称谓 + 姓名、“付玉清付总”等写法），装了 jieba 时用其词典排除常见词并补充识别；本公司人员、同行品牌、客户名称片段已排除。2026-09-18 在正式库上抽样核对，全名类的准确率约九成，仍会有少量公司简称、药品名被当成人名，报表里高亮了抽到的名字便于核对。`reports/` 不进仓库。在 CRM 补录联系方式后重新生成即可更新。

## 7. 手机访问（0.6，经 Tailscale）

数据在这台 Mac 上，手机通过 Tailscale 组成的私有网络连到它，不经过公网、不需要域名。Mac 睡眠或关机时手机就看不到。

**一次性准备**

1. Mac 上安装 Tailscale（`brew install --cask tailscale`，或到 tailscale.com/download 下载），打开后用你的账号登录。
2. 手机上安装 Tailscale App（App Store / 应用商店），用同一个账号登录。
3. Mac 上把前台改为可被 Tailscale 访问（会自动生成访问密码并写入 `.env`，命令执行后打印地址与密码）：

```
cd ~/newxtools && .venv/bin/python scripts/install_launchd.py --web --host 0.0.0.0
```

**日常使用**：手机浏览器打开 `http://<Mac 的 Tailscale 地址>:8790`（形如 http://100.x.x.x:8790），首次输入账号密码，之后浏览器会记住。iPhone 上用 Safari 的“分享 → 添加到主屏幕”可以像 App 一样打开。Mac 的 Tailscale 地址用 `tailscale ip -4` 查看；开启 MagicDNS 后也可以用机器名访问。

**两道门**（见 `web/auth.py`）

| 门 | 规则 |
|---|---|
| 来源地址 | 只放行本机与 Tailscale 网段（100.64.0.0/10、fd7a:115c:a1e0::/48）。同一 Wi-Fi 下的其他设备、公网扫描都会收到 403。需要局域网访问时在 `.env` 设 `XTOOLS_WEB_ALLOW=192.168.1.0/24` 之类 |
| 账号密码 | HTTP Basic，凭证为 `.env` 里的 `XTOOLS_WEB_USER` / `XTOOLS_WEB_PASSWORD`（`.env` 不进仓库）。**本机 127.0.0.1 访问始终免密**，日常在 Mac 上用不受影响；绑定非本机地址却没设密码时，除本机外一律拒绝（503） |

改密码：编辑 `.env` 的 `XTOOLS_WEB_PASSWORD` 后 `launchctl kickstart -k gui/$(id -u)/com.microwants.xtools-web`。改回只允许本机：`.venv/bin/python scripts/install_launchd.py --web`（不带 `--host`）。

**和别的 VPN（Surfshark 等）一起用**：Tailscale 缺省只接管自己的网段（100.64.0.0/10），其余流量仍走原来的 VPN，Mac 上通常可以共存；出问题多半是三件事——对方 VPN 的 kill switch 把 Tailscale 的流量一并拦掉（关掉它，或在 Surfshark 的 Bypasser 里把 Tailscale 加入绕过）、Tailscale 启用了 exit node（不要开，它需要独占网络）、两者的内网段撞车。**手机上不能共存**：iOS 与 Android 同一时刻只允许一个 VPN 生效，要看数据就切到 Tailscale，看完切回去。

想在公司或家里免去切换，可以让同一 Wi-Fi 下的手机直接走局域网：

```
cd ~/newxtools && .venv/bin/python scripts/install_launchd.py --web --host 0.0.0.0 --allow-lan
```

它会把本机网卡所在的私有网段（如 192.168.1.0/24；VPN 的 utun 接口不算）写进 `.env` 的 `XTOOLS_WEB_ALLOW`，手机连同一 Wi-Fi 时用 `http://<Mac 的局域网 IP>:8790` 打开，不必开任何 VPN；出门在外再用 Tailscale 地址。代价是同一网络内的其他设备也能访问（仍要账号密码），换了网络环境（IP 段变化）需要重跑一次。

**换别的组网方案**：前台不绑定 Tailscale。裸 WireGuard、ZeroTier、软路由或 NAS 自带的组网都一样用，只要在 `.env` 里把你的网段加进白名单（例如 WireGuard 常用的 `XTOOLS_WEB_ALLOW=10.6.0.0/24`），再重启前台即可，其余不变。裸 WireGuard 需要自己解决可达性：Mac 与手机都在 NAT 后面时连不起来，要么有一台带公网 IP 的机器做中转，要么 Mac 这边能做端口映射（固定公网 IP 或 DDNS + 路由器转发 UDP 端口）。Tailscale 省掉的就是这一步。

**连通速度**：手机与 Mac 在同一 Wi-Fi 下，Tailscale 会直接走局域网，速度与本机相当；手机用移动网络时先尝试打洞直连，打不通则经 Tailscale 的中继服务器（在境外，会明显变慢）。登录与密钥协商需要访问 tailscale.com，国内偶有不稳。

**手机上的页面**：窄屏下导航可左右滑动，筛选栏折叠为“筛选”按钮，列表由表格改为一行一张卡片（卡片标题是客户 / 产品 / 供应商等主体），图表点按柱子看数值，详情抽屉全屏。多年份对比、现金流这类宽表也按卡片竖排。导出 Excel 在手机上会下载文件，用表格类 App 打开。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 页面提示“无法连接前台服务” | 服务未运行：执行第 2 节安装命令，或 `launchctl start com.microwants.xtools-web` |
| 右上角提示“超过 2 小时未更新” | 同步任务未跑：看 `scripts/sync.py --status` 与 logs/sync.log |
| 数字与 CRM 不一致 | 先看“数据截至”时间；订单表每周全量一次才会体现删除；金额口径见第 4 节 |
| 页面很慢 | 看 logs/web.log 中每个接口的耗时；正式库上各接口通常在 100 毫秒内。重启服务会重新检查索引：`launchctl kickstart -k gui/$(id -u)/com.microwants.xtools-web` |
| 工作日志里出现“日期异常”或“无日期” | 是 CRM 里录入的原始日期（例如把 2024 写成 2224、或未填日期），前台只做标记不改数据；在 CRM 中更正后，行动记录每周全量重拉时更新（其余表按各自策略更新） |
| 采购单“供应商”为空、订单发票类型等不显示 | 0.5 新增的列还没回填：`cd ~/newxtools && .venv/bin/python scripts/sync.py --dict && .venv/bin/python scripts/sync.py --rebuild --table contract,purchase`，然后重启前台 |
| 订单详情里自定义字段标“（代码）” | CRM 未返回该字段的选项字典（`sync.py --dict` 日志里列为“未配置选项”），或字段本身是文本 / 数字 |
| 手机打不开，提示无法连接 | 看 Mac 是否醒着、Tailscale 两端是否都登录同一账号（手机 App 里应能看到这台 Mac 在线）；前台是否绑了 0.0.0.0（`launchctl list \| grep xtools-web` 后看 logs/web.log 首行“访问控制”） |
| 手机上提示 403 | 来源不在 Tailscale 网段，通常是手机没走 Tailscale（App 里的开关没打开），或用的是局域网 IP 而不是 100.x 地址 |
| 手机上一直要密码 | 密码见 `.env` 的 XTOOLS_WEB_PASSWORD；输错会反复弹出。密码里没有容易混淆的字符（无 0/o/1/l/i） |
| 安装时提示“端口已被其他程序占用” | 换一个端口安装：`install_launchd.py --web --port 8801`，之后用新端口打开。8765 这类常见端口容易被本机其他应用占用，缺省端口因此选用 8790 |
