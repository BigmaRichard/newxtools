# XTools OPEN API 文档版本变更记录

麦可旺志 Microwants · xtools 优化项目

本记录用于跟踪 XTools（超兔）提供的《XToolsCRM OPEN API》apizza 导出文档各版本之间的差异，以及本仓库随之做出的调整。比对方法：两版 HTML 分别解析为结构化数据（接口名、请求参数表、详细说明、返回示例），逐接口逐行比较；新增接口的签名示例已用 md5 复算核验。

## 2026-09-01 版（对比 2026-05-22 版）

比对日期：2026-09-16。接口数 68 → 71；其余 67 个接口的参数表、详细说明与返回示例逐行一致，仅 1 个接口有内容补充。

### 新增接口（3 个）

| 序号 | 接口 | cmd | dt | 要点 | 本仓库对应 |
|---|---|---|---|---|---|
| 9 | 联系人修改接口 | api.update | contact | data.id 必填且不能为 0；不能传 cu_sn（客户不可改，否则报“对应客户不能修改，无法保存”）；可改姓名、性别、称谓、部门、职务、负责业务、电话、手机、传真、邮箱、QQ、微信、微信昵称、QQ 昵称、家庭电话 / 住址 / 邮编、生日、备注、证件类型与号码、类型 islinkman，以及用户画像字段 ext_selN / ext_itemN；示例带 extend=1 | `xt.customers.update_contact(data)`（校验 id 与 cu_sn） |
| 70 | 采购退货单读取接口 | api.output | purreturn | 只读；主单 + 明细 purrtnitem；status 0 待处理;2 执行中;3 结束;4 终止；st_libout 出库状态；st_hk 退款状态 | `xt.finance.purchase_returns()` / `get_purchase_return(id)` |
| 71 | 订单退货单读取接口 | api.output | libreturn | 只读；主单 + 明细 rtnitem；co_id 为订单 ID；st_libin 入库状态；st_hk 退款状态 | `xt.orders.returns()` / `get_return(id)` |

签名示例核验（均一致）：联系人修改 47572be8b3d7f6ae4acff453a3b319d1；采购退货单读取 6407574abce5dc67958cbceb4b50de2c；订单退货单读取 250e4f0d49cf7b342eb2faafe8a7f651。联系人修改示例的 param 中含单引号（"py":"zhang'an an"），说明签名文本不做额外转义。

### 内容补充（1 个）

| 序号 | 接口 | 变化 | 本仓库对应 |
|---|---|---|---|
| 25 | 维修工单读取接口 | 新增“字段说明”：主单字段（id、No.、who、date、recv_time、cu_sn、name、tel、phone）、副表 repairinfo 字段，以及此前未提及的 goods 明细（id、pid、pro_name、model、spec、amount、un_price、sum、rep_sum 厂家承担金额、memo） | 新增 `xt.repairs`（`RepairAPI`：get / iter / create） |

### 其他

- 侧栏新增“状态码”条目，但正文仍无内容；错误码表仍需向 XTools 索取。
- 序号变化：自“联系人修改接口”（新 9 号）起，原有接口序号顺延 1 位；两个退货单读取接口排在末尾（70、71）。
- 原文档的不一致之处（http/https 混用、个别示例拼写）本版未修订。

### 对接入方案的影响

1. 《01_接入准备清单》风险 R10 中“客户主表修改不处理联系人”的限制已由联系人修改接口解决；联系人新增仍通过客户写入接口的 contact 数组，联系人删除仍无接口。
2. 《04_首批四模块字段映射》新增 contact 修改字段、libreturn / purreturn 字段。
3. 《05_同步方案设计》读取策略表加入两个退货单表（lastid 增量 + 活动单据重拉）；P2 阶段纳入退货单只读镜像。
4. 客户端版本 0.1.0 → 0.2.0；离线测试 44 → 49 项。
