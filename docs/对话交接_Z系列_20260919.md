## 1. 虎客好店是什么

XTools 一体云自带的微信小程序商城模块，不是独立系统，数据全部落在 CRM 既有表内。

| 环节 | 落点 |
|---|---|
| 店铺 | `hm_shop` 表，后台 `/sys/hookmember/shop/`。正式库 1 条：「麦可旺志小程序店铺」，介绍「色谱配件」，LOGO / 背景图 / 咨询电话 / 邀约会员介绍文字均未填 |
| 商品 | CRM 产品表 `product.hm_shop`（0 不上架 / 1 上架 / 2 精选）。正式库 7,862 条产品记录中 13 条上架，均为 COSMOSIL 成品柱，`price` 全为 0，`costprice` 有值 |
| 会员 | 平台自动在 CRM 建「个人客户 + 联系人」：客户名「姓名 手机号」（type=1、cu_from=-1、无客户编号），联系人名「虎客会员 + 16 位标识」。正式库 15 条会员联系人，11 条建于 2019-04（仍挂 B1、未改名），2 条建于 2026-01-26（客户 15034 高小姐 / M56、15035 肖婷姣 / M77） |
| 下单 | 报价 / 预下单（`price` 表），分类「来自虎客」，主题 = 虎客订单号 `HM` + 16 位。正式库 4 条，2026-01-26，合计 49.00 元。收货信息写在「交付说明」文本里 |
| 转订单 | 预下单详情点「确认生成订单」→ `contract`。例：214 于 2026-01-26 11:18 由陈海云确认生成订单 25501；该订单其后已从 CRM 删除（网页查 25501 返回「未发现」），镜像库同样没有，两边一致 |
| 分销佣金 | `/xcrm/contract/commission/`，0 条，未启用 |
| 相关页面 | `/xcrm/desktop/recommend.xt`（上架说明）、`/sys/hookcard/`（虎客名片访客消息，需绑微信，每次读取上限 200 条且需一次处理完） |

`/sys/hookmember/` 目录返回 403，除 `shop` 外的子页（member / goods / order / set / card / coupon 等）均为 404，可判断会员与订单没有独立管理页。

## 2. 接口能力与缺口

| 环节 | 接口 | 状态 |
|---|---|---|
| 读上架状态 | `api.output` · `product` | 可用，返回 `hm_shop` 展示文本、`wxflag`、`ydh_sn` / `jd_sn` / `tb_sn` / `tm_sn` |
| 写上架状态 | `api.update` · `product` | `price` 文档已列可写；`hm_shop` **文档未列**，需在测试公司 ne2993 验证 |
| 读预下单 | 无 | 71 个接口中报价单只有写入（20）与修改（21），**没有读取接口** |
| 读转化后订单 | `api.output` · `contract` | 可用，已在同步链路 |
| 会员 | `api.output` · `customer`（extend=1） | 可用，会员即普通个人客户与联系人 |

镜像侧：`sync/specs.py` 的 product 列未含 `hm_shop`、`wxflag` 等（原始 JSON 表里有，本轮数据即由此取得）。

## 3. 三个方向的落地要点

1. **商品与价格上架自动化**：先在测试公司验 `api.update` 能否写 `hm_shop`（0/1/2）。可写则做 `scripts/hm_shop.py`（筛选 → 批量上架 / 精选 → 写售价 → 回读核对）；不可写则脚本只出待上架清单，上架动作用产品列表批量编辑。镜像 product 补 `hm_shop` 等列并 `--rebuild --table product`，前台产品页加「好店」列与「已上架且售价为 0」提示。
2. **微店订单纳入前台监控**：受第 2 节缺口限制，先以已转化订单为准（来源识别口径待定），再考虑列表导出入库补「未转化」部分，同时向 XTools 询问是否有报价单读取接口。
3. **虎客会员客户治理**：现有镜像数据即可出清单（按联系人姓名前缀识别），做手机号比对去重、指派所有者、补联系方式；前台客户页与联系人页加「虎客会员」标识与筛选。
