# XTools OPEN API 接口机制与签名说明

麦可旺志 Microwants · xtools 优化项目 · 2026-09-11
依据：《XToolsCRM OPEN API》文档（2026-05-22 导出）。本文所述签名算法已用文档中 29 组“计算前字符串 / md 计算结果”示例逐一核验（见 `tests/test_sign.py`），结果一致。

## 1. 请求结构

- 统一入口：`POST https://crm.xtcrm.com/open/index.xt`（文档中部分接口写为 http，客户端统一使用 https）。
- 请求体为表单字段（application/x-www-form-urlencoded，UTF-8）：

| 字段 | 类型 | 说明 |
|---|---|---|
| cmd | string | 接口命令，见第 2 节 |
| appid | string | 开发公司应用 ID |
| stamp | string | 当前时间戳，10 位秒级 |
| upr | JSON 字符串 | 登录信息：登录时为 comkeyid/com/part/md；其余请求为 {"sid": "..."} |
| param | JSON 字符串 | 业务参数；登录时为 `[]` |
| md | string | 请求签名，见第 3 节 |

- 响应为 JSON：

```
成功：{"ok":1, "ret":{...}}
失败：{"ok":0, "err":{"errno":20101, "errmsg":"session已经失效，请进行重新登录!"}}
```

`ret` 内通常另有 `ok`（业务结果）与 `msg`（文字说明）；读取类接口的数据在 `ret.data`，写入类接口成功时部分返回新记录 `ret.id`。

## 2. 命令（cmd）与数据表（dt）

| cmd | 作用 | param 结构 |
|---|---|---|
| user.login | 登录换取 sid | `[]` |
| api.output | 读取 | `{"dt":..., "id"|"lastid":..., 其他过滤}` |
| api.input | 写入（新建） | `{"dt":..., ["extend":1,] "data":{...}}` |
| api.update | 修改 | `{"dt":..., ["extend":1,] "data":{定位条件 + 变更字段}}` |
| api.cmdact | 动作 | `{"dt":..., "data":{"act":..., ...}}` |
| api.fieldinfo | 字段信息 | `{"dt":..., "field":...}` 数据字典；`"act":"dbcn"` 字段中文名；`"act":"pr2nm"` 人员对照 |
| api.chgown | 客户转移 | `{"dt":"customer", "id"|"sn":..., "owner":...}` |
| api.downfile | 附件列表 | `{"dt":..., "id":..., ["field":...]}` |

dt 取值即数据表分类，如 customer、customerext、cuview、contract、contract0、sendgoods、sr_notice、libin、libout、libn、product、csstree、prod_alias、price、purchase、pay_plan、gathering、gathering_note、bill、bill_apply、action、opport、project、cost、costdetail、b_trip、repairinfo、jk_collect、ask_price_note、mes_flow、mes_process、process_exec、user。完整对照见《03_接口清单》。

动作（act）取值：getOtherItems、sendGoods_no_stock（contract）；libinok（libin）；liboutok（libout）；chg_str_ps（product）；chgst、exc（sr_notice）；erp_libn（libn）；kaipiao（bill_apply）；preview（mes_process）。

## 3. 签名算法

### 3.1 请求签名 md

```
md = md5( param字符串 + stamp + upr字符串 + cmd + appkey )
```

要求：

1. 参与签名的 param、upr 字符串与表单中实际发送的字符串逐字一致。
2. JSON 序列化采用紧凑格式（无空格、无换行），中文不转义（Python：`json.dumps(obj, ensure_ascii=False, separators=(",", ":"))`）。
3. md5 以 UTF-8 编码计算，输出 32 位小写十六进制。

文档示例（客户读取）：

```
param : {"dt":"customer","id":10}
stamp : 1549876028
upr   : {"sid":"4abda94f27512666f079e288ab44a287"}
cmd   : api.output
appkey: open1slslslsdldlsdlds
拼接  : {"dt":"customer","id":10}1549876028{"sid":"4abda94f27512666f079e288ab44a287"}api.outputopen1slslslsdldlsdlds
md    : 79bdc07d245290beea7da0c9ec0fbb58
```

### 3.2 登录验证码 upr.md

```
upr.md = md5( stamp + comkey + com + part )
upr    = {"comkeyid":"<comkeyid>","com":"<com>","part":"<part>","md":"<upr.md>"}
```

文档示例：stamp 1527746854，comkey xtoolsplusd002sjsjsj，com d002，part 为空 → 拼接 `1527746854xtoolsplusd002sjsjsjd002` → md5 `d79d4e33a7771d8f0473f1bc0bd12f8e`。注意示例中 comkey 与 upr 内的 comkeyid（xtoolsplusd002）不同。

登录请求整体签名同 3.1，其中 param 为 `[]`，cmd 为 user.login。

## 4. 登录与会话

1. 登录成功返回 `ret.sid`（另有 com、part）。之后各请求 `upr = {"sid": sid}`。
2. 登录接口 10 秒内只能调用一次，超出返回 errno 30103。
3. sid 原则上到次日凌晨服务器重启失效；服务器重启或管理员“踢掉所有用户”会提前失效。文档建议以 30 分钟为准。
4. 需要重新登录的判定：`ok == 0` 且 `err.errno` 为 20101 或 20102。

客户端实现：sid 与上次登录时间写入 `.xtools_session.json`；发起请求前若距上次登录不足 10 秒则等待；收到 20101/20102 时强制重登并重试一次；收到 30103 时等待 10 秒重试一次。

## 5. 读取与分页

- `lastid`：上次读取的末条 id，服务器返回 id 大于该值的记录，每次至多 100 条；`id` 参数存在时 lastid 不起作用。
- 支持增量时间过滤 `lasttime`（时间字符串或 10 位时间戳）的表：customer、product、libout、sr_notice、cost（文档明示）。
- 支持按编号定位的读取：customer（sn、name）、contract（"No."）、product（sn）、sendgoods / gathering / gathering_note（memo 精确匹配，可用于唯一性校验）。
- `extend=1` 返回扩展字段（customer、contract、opport 等）。

客户端 `iter_output(dt, **filters)` 以 lastid 循环直到返回空页或 id 不再增长。

## 6. 写入与修改的语义

| 场景 | 规则（依据文档） |
|---|---|
| 新建 | data 中 id 不传或为 0；客户以 cu_sn（客户编号）关联；产品以 prod（产品编码）关联，订单扩展模式可用品名 / 型号 / 规格 / 批次匹配 |
| 修改客户 | 只改客户表，不处理联系人；以 id 或 sn 定位；修改 sn 时需提供 id |
| 修改订单 / 报价单 | 只传变化字段，但明细（goods / pricedetail）为全量替换：未提供的已有明细被删除，已存在的按修改，新出现的按添加；订单客户 cu_sn 不可修改 |
| 修改计划回款 | 客户 cu_sn 不可修改 |
| 修改批单报销 | aprv_status = 4（同意）或 5（否决）会终结 CRM 审批且不可再操作；仅记录状态时用 aprv_st |
| 入库 / 出库 | 先写入取得 ret.id，再以该 id 调用 libinok / liboutok 完成 |
| 收发货通知单 | 读取 → 写入外部系统 → 回写 API 已读（chgst status=2） → 外部执行 → 回写执行结果（exc） → 外部库存变更（erp_libn）；执行前需再次确认通知单未关闭 |
| 所有者 | 写入记录的所有者默认为登录人；客户需另调 api.chgown，订单 / 报价单可在 data 中给 who / sname |

## 7. 错误处理约定（客户端）

| 情况 | 异常类型 | 处理 |
|---|---|---|
| 网络异常 / HTTP 非 200 / 响应非 JSON | XToolsTransportError | 读取类自动重试 3 次；写入类不重试 |
| ok=0，errno 20101/20102 | XToolsSessionExpired | 自动重登并重试一次 |
| ok=0，errno 30103 | XToolsLoginThrottled | 等待 10 秒重试一次 |
| ok=0，其他 errno | XToolsApiError | 抛出，由调用方处理 |
| ok=1 但 ret.ok=0 | XToolsBusinessError | 抛出，msg 为 CRM 返回的原因（如编号重复、客户不存在） |

## 8. 时间与编码约定

- 日期字段为 `YYYY-MM-DD`；时间字段为 `YYYY-MM-DD HH:MM:SS`；时间戳为 10 位秒级。
- 省份为 1–35 的编码（1 安徽 … 31 浙江，32 香港，33 澳门，34 台湾，35 其它），城市、区县为文本。
- 人员以 part（如 B1、M9）标识；部分接口接受姓名并自动转换为 part。
- 自定义字段：客户表为 ext_itemN / ext_selN / ext_dateN，订单、合同、采购、报价为 jN；字段含义各公司不同，用 api.fieldinfo（dbcn）取得中文名。
