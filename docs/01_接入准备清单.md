# XTools（超兔）CRM OPEN API 接入准备清单

麦可旺志 Microwants · xtools 优化项目 · 2026-09-11，2026-09-16 按 2026-09-01 版文档修订
依据：《XToolsCRM OPEN API》（apizza 导出，文件名 OPEN API_20260901.html，共 71 个接口；版本差异见《00_文档版本变更记录》）

## 1. 目的与范围

本清单用于在正式联调前完成凭证、环境、配置与风险确认。首批接入范围为四个业务模块：客户与联系人、订单与发货、产品与库存、财务（回款 / 开票 / 付款 / 采购）。技术栈为 Python 3.9+，客户端代码位于仓库 `newxtools` 的 `xtools/` 包。

## 2. 凭证与开通

### 2.1 需向 XTools 索取的六项凭证

网页登录（xtools.cn）的账号密码不能用于 Open API。官网对 API 对接的说明为“联系当前专员”，即由客户专员为公司账号开通 Open API 并提供以下信息：

| 项 | 环境变量 | 说明 | 文档示例 |
|---|---|---|---|
| 应用 ID | XTOOLS_APPID | 开发公司的应用 ID，随每次请求明文发送 | open00001_sajdjsjsj |
| 应用密钥 | XTOOLS_APPKEY | 参与每次请求 md 签名，不发送 | open1slslslsdldlsdlds |
| comkeyid | XTOOLS_COMKEYID | XTools 分配给客户公司的 comkeyid，明文放在登录 upr 中 | xtoolsplusd002 |
| comkey | XTOOLS_COMKEY | 客户公司 key，参与登录验证码计算，不发送 | xtoolsplusd002sjsjsj |
| 公司编码 | XTOOLS_COM | XToolsCRM 中的客户公司内部编码 | d002 |
| 登录人 part | XTOOLS_PART | 接口登录人，缺省 B1；写入数据的默认所有者 | B1 |

说明：文档示例中 comkey（xtoolsplusd002sjsjsj）与 comkeyid（xtoolsplusd002）并不相同，签名核验确认登录验证码使用的是 comkey。索取时需分别确认两者，避免只拿到一项。

### 2.2 需同时确认的开通事项

1. Open API 功能是否已在公司账号上启用，以及开通的接口范围（读取 / 写入 / 修改 / 动作是否均开放）。
2. 是否启用“外部库存”功能。收发货通知单读取、状态变更、执行接口以及外部库存变更接口在未启用时不可调用（文档明确说明）。
3. 是否有 IP 白名单、调用频率或每日调用量限制。文档仅说明登录接口 10 秒内只能调用一次，其余未说明。
4. 是否提供测试公司（独立的 com）或测试数据区，以便写入类接口先在非生产数据上验证。
5. 服务器对 stamp（时间戳）与服务器时间的偏差是否校验、容差多少。
6. 同一 part 重复登录时，旧 sid 是否立即失效（影响多进程 / 多服务器共用凭证的部署方式）。
7. 附录“状态码”在导出文件中为空（2026-09-01 版侧栏已有该条目但仍无正文），需索取完整错误码表。正文中出现的编号：20101 / 20102（session 失效）、30103（登录过于频繁）。

### 2.3 登录人 part 的选择

建议为接口单独设立一个 CRM 用户（如“接口专员”），并以其 part 作为 XTOOLS_PART：

- 接口的数据可见范围与写入权限由该用户的 CRM 权限决定；
- 写入的客户、订单等记录的所有者默认为该登录人，需要指定所有者时通过“客户转移接口”或在 data 中提供 who / owner 字段；
- 便于在 CRM 日志中区分接口操作与人工操作。

## 3. 环境准备

| 项 | 要求 |
|---|---|
| 运行环境 | Python 3.9 及以上；依赖仅 requests |
| 网络 | 出网访问 https://crm.xtcrm.com（443）；文档中部分接口写的是 http，客户端统一使用 https |
| 代码位置 | GitHub 仓库 BigmaRichard/newxtools（根目录即本接入包） |
| 凭证保存 | 仓库根目录 `.env`（已在 .gitignore 中，不入库）；服务器部署时改用环境变量或密钥管理 |
| 会话缓存 | `.xtools_session.json`，保存 sid 与上次登录时间，避免触发登录限频 |

## 4. 配置与验证步骤

第一步，安装依赖并运行离线测试（不需要凭证，验证签名算法与客户端逻辑）：

```
cd newxtools && python3 -m pip install -r requirements.txt && python3 -m pytest tests -q
```

第二步，复制 `.env.example` 为 `.env` 并填入六项凭证。

第三步，运行只读冒烟测试（登录、用户读取、字段字典、四模块各读一页，不写入数据）：

```
cd newxtools && python3 scripts/smoke_test.py --verbose
```

第四步，导出数据字典、字段中文名与人员对照，作为字段映射的依据：

```
cd newxtools && python3 scripts/dump_dictionary.py --out dictionary
```

## 5. 验收标准

冒烟测试通过的定义：

1. 登录接口返回 sid；10 秒内重复运行时复用缓存 sid，不再触发登录。
2. 用户读取、人员对照（pr2nm）、字段名称（dbcn）、客户阶段字典（cu_status）均返回数据。
3. 客户、订单、产品、回款记录、订单退货单各读取到一页数据（空表返回空数组也视为通过）。
4. 收发货通知单读取在未开通外部库存时返回明确错误；开通后返回数据。
5. 全过程无签名错误（若出现 md 校验类错误，优先核对 appkey 与 comkey 是否互换）。

## 6. 已知限制与风险

| 编号 | 事项 | 影响 | 应对 |
|---|---|---|---|
| R1 | 读取接口每次至多 100 条，按 lastid 翻页，以 id 递增为前提 | 全量同步需多次请求 | 客户端 iter_output 已封装；增量优先用 lasttime（客户、产品、出库单、通知单、报销支持） |
| R2 | 登录 10 秒内只能调用一次；sid 以 30 分钟为准，服务器重启或“踢掉所有用户”后失效 | 多进程并发登录会被限频 | sid 文件缓存 + 20101/20102 自动重登；部署为单一同步进程 |
| R3 | 写入接口无幂等键，重复提交会产生重复单据 | 网络超时后重试可能重复写入 | 写入不自动重试；提交前按 sn / No. / memo 查重（发货单、回款记录、计划回款支持 memo 精确匹配） |
| R4 | 订单、报价单修改时明细为全量替换：未提供的已有明细会被删除 | 局部修改可能误删明细 | 修改前先读取完整明细再回写 |
| R5 | 枚举值依赖各公司的数据字典（客户阶段、来源、付款方式、单位等） | 硬编码枚举会出错 | 先运行 dump_dictionary.py，映射表以字典为准 |
| R6 | 产品表读取时部分枚举返回展示文本（如“是”“正常”），写入需用数字 | 读写字段格式不对称 | 映射层做双向转换 |
| R7 | 文档存在不一致处：http/https 混用、示例字段拼写（如发货明细中的 ns / sn）、附录状态码为空 | 个别参数需实测 | 联调阶段逐接口验证，结果记录在项目文档 |
| R8 | 签名为 md5 明文拼接，appkey / comkey 泄露即可伪造请求 | 安全风险 | 凭证只放环境变量或密钥管理；日志脱敏（客户端已实现） |
| R9 | 附件下载 URL 有效期约 2 小时 | 不能持久保存链接 | 需要时即时获取并下载 |
| R10 | 客户主表修改不处理联系人（2026-09-01 版起可用联系人修改接口按 id 单独修改，但不能改所属客户）；联系人无删除接口；订单客户（cu_sn）不可修改；计划回款客户不可修改 | 部分变更无法通过修改接口完成 | 按文档规则设计业务流程，必要时新建记录 |
