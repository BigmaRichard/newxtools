# P0 只读镜像使用说明（XTools CRM → 本地 SQLite）

麦可旺志 Microwants · xtools 优化项目 · 2026-09-17

## 1. 作用与边界

把 XTools CRM 的业务数据按表同步到本地 SQLite 文件 `data/xtools_mirror.sqlite`，供报表、查询工具与其他系统读取。只调用读取类接口（api.output / api.fieldinfo），不向 CRM 写入任何数据。运行账号为正式账号（`.env` 中 com=pc7699）；写入类验证脚本（roundtrip_test.py）对正式账号默认拒绝执行。

联网脚本只能在 Mac 终端运行（Claude 会话与本地 VM 均无法访问 crm.xtcrm.com）。

## 2. 首次运行与定时

首次全量拉取（含字典、字段中文名、人员对照），并安装每 30 分钟一次的 launchd 定时任务：

```
cd ~/newxtools && .venv/bin/python scripts/sync.py --init && .venv/bin/python scripts/install_launchd.py
```

之后的日常命令：

| 目的 | 命令 |
|---|---|
| 手动增量一次 | `cd ~/newxtools && .venv/bin/python scripts/sync.py` |
| 查看各表游标与上次结果 | `cd ~/newxtools && .venv/bin/python scripts/sync.py --status` |
| 强制全量重拉（含删除检测） | `cd ~/newxtools && .venv/bin/python scripts/sync.py --full` |
| 只同步指定表 | `cd ~/newxtools && .venv/bin/python scripts/sync.py --table customer,contract` |
| 只刷新字典 | `cd ~/newxtools && .venv/bin/python scripts/sync.py --dict` |
| 规格改动后重建规范化表 | `cd ~/newxtools && .venv/bin/python scripts/sync.py --rebuild` |
| 卸载定时任务 | `cd ~/newxtools && .venv/bin/python scripts/install_launchd.py --uninstall` |

日志：`logs/sync.log`（程序日志，自动轮转）、`logs/launchd.out.log` / `launchd.err.log`（定时任务输出）。同一时刻只允许一个同步进程（`data/sync.lock`）。

## 3. 同步策略

| 表（dt） | 规范化表 | 方式 | 说明 |
|---|---|---|---|
| user、csstree、prod_alias | crm_user、product_class、product_alias | 每次全量 | 小表 |
| customer（extend=1） | customer + contact | lasttime 增量，重叠 30 分钟；每周全量 | 联系人从客户记录拆出 |
| customerext | customer_ext | lastid 新增；每日全量 | 列按出现的键动态添加 |
| product | product | lasttime 增量；每周全量 | |
| contract（extend=1） | contract + contract_goods | lastid 新增；每次重拉 status=1 与近 90 天；每周全量 | 订单在 CRM 内部称“合同” |
| contract0 | contract0 | lastid 新增；每日全量 | 合同 |
| sendgoods | sendgoods + sendgoods_items | lastid 新增；每日全量 | |
| libout | libout + libout_items | lasttime 增量；每周全量 | |
| libreturn、purreturn | order_return(+items)、purchase_return(+items) | lastid 新增；每日全量 | 2026-09-01 版新增接口 |
| purchase | purchase + purchase_items | lastid 新增；每日全量 | |
| pay_plan、gathering、gathering_note | 同名 | lastid 新增；每日全量 | 计划回款与回款记录状态变化靠每日全量捕获 |
| opport（extend=1） | opport | lastid 新增；每日全量 | |
| action | action | lastid 新增 | 行动记录视为只增 |
| sr_notice | sr_notice + sr_notice_items | lastid 新增；每日全量；可选 | 未启用外部库存时跳过 |

全量拉取时，镜像中存在而 CRM 未返回的 id 标记为删除（raw_records.deleted_at 与规范化表 _deleted_at），不物理删除；记录再次出现时自动取消标记。

无读取接口、因此无法镜像的对象：开票记录（bill，只有写入接口）、入库单（libin，只有写入接口）、联系人单独读取（随客户记录返回）。

## 4. 库结构

| 表 | 内容 |
|---|---|
| raw_records | 每条记录的原始 JSON（dt + id 主键）、内容哈希、首次 / 更新 / 末次抓取时间、删除标记 |
| sync_state | 每表游标（lastid、lasttime、上次全量时间）与上次运行结果 |
| sync_log | 每次运行每表的行数、新增、更新、删除、状态 |
| dictionaries | 数据字典（dt, field, key → value, flag）；人员对照存于 dt=user, field=pr2nm |
| field_names | 字段英文名 → 中文名 |
| 规范化表 | 见第 3 节；列名与接口字段一致（"No." 存为 no_），值以文本存储，金额与数量在视图中转换为数值 |

报表视图（可直接用 DB Browser for SQLite、DataGrip、Excel ODBC 或 Python 读取）：

| 视图 | 内容 |
|---|---|
| v_contract | 订单 + 客户名称、金额（数值）、状态、发货状态 |
| v_contract_goods | 订单明细 + 产品名称 / 型号（按产品编码关联产品表） |
| v_receipt | 回款记录 + 客户名称 |
| v_receivable | 计划回款 |
| v_monthly_sales | 按签约月汇总的订单数与金额 |
| v_monthly_receipt | 按月汇总的回款笔数与金额 |
| v_customer_overview | 客户 + 订单数、订单金额、回款金额、联系人数 |

客户关联规则：订单等表的 cu_sn 为客户编号；客户无编号时接口返回 "[id:N]"，视图按两种形式同时匹配。

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| 登录被限频（30103） | 客户端自动等待 10 秒重试；避免同时手动运行两个同步 |
| 某表状态为 error | 看 `--status` 的错误列或 logs/sync.log；单表失败不影响其他表，下次运行自动重试 |
| sr_notice 状态为 skipped | 正常：未启用外部库存 |
| 规格（specs.py）新增列 | 程序启动时自动补列；历史数据需 `--rebuild` 回填 |
| 换库文件 | `--db` 指定路径；游标随库文件走 |
| 切换账号 | 编辑 `.env`（测试 / 正式各三行）；不同账号请使用不同的 `--db` 文件，避免混数据 |
