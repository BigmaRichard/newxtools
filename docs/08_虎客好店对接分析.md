# 虎客好店（微店）对接分析

MW · xtools 优化项目 · 2026-09-19 · 依据正式公司（pc7699）网页后台实勘与本地镜像库核对

> 本文为对接前的现状分析与方案建议。涉及的页面路径均为 XTools 一体云后台（`t30.xtcrm.com`）实际访问结果，数据量取自 2026-09-19 的只读镜像库。

---

## 1. 结论摘要

| 项 | 现状 |
|---|---|
| 系统归属 | 虎客好店是 XTools 一体云自带的微信小程序商城模块，不是独立系统，全部数据落在 CRM 既有表里 |
| 店铺 | 已建 1 个：「麦可旺志小程序店铺」，介绍「色谱配件」。LOGO、背景图、咨询电话、邀约会员介绍文字均未填写 |
| 商品来源 | CRM 产品表的 `hm_shop` 字段（0 不上架 / 1 上架 / 2 精选）。正式库 7,862 条产品记录中 13 条为「上架」，均为 COSMOSIL 成品色谱柱 |
| 价格 | 13 个上架品的 `price` 均为 0.0000（仅 `costprice` 有值）。小程序端的价格表现需实机核对 |
| 会员 | 会员在 CRM 落成「个人客户 + 联系人」两条记录：客户名为「姓名 手机号」，联系人名为「虎客会员 + 16 位标识」。正式库共 15 条会员联系人，其中 2 条建于 2026-01-26 |
| 下单 | 会员下单生成**报价 / 预下单**（`price` 表，分类「来自虎客」，主题即虎客订单号 `HM…`），需人工点「确认生成订单」才进合同表。正式库 4 条，均为 2026-01-26，合计 49.00 元 |
| 分销佣金 | 「虎客好店佣金列表」为 0 条，分销功能未启用 |
| 接口缺口 | OPEN API 对报价单只有写入与修改接口，**没有读取接口**，预下单无法经 OPEN API 拉入镜像库；转成订单后可由 `contract` 读取覆盖 |

关于本轮确定的三个方向，可执行程度依次为：会员客户治理（现有数据即可完成）、商品与价格上架自动化（需先验证 `hm_shop` 是否可写）、微店订单前台监控（受报价单无读取接口限制，需另择取数方式）。

## 2. 模块入口与页面

| 页面 | 路径 | 作用 |
|---|---|---|
| 微店（店铺设置） | `/sys/hookmember/shop/` | 店名、介绍、邀约会员介绍文字、咨询电话、背景图片、微店 LOGO；后台表名 `hm_shop` |
| 商品上架说明 | `/xcrm/desktop/recommend.xt` | 说明经产品列表编辑或批量编辑「虎客好店」字段完成上架，精选品在商家主页展示 |
| 报价 / 预下单列表 | `/xcrm/tracing/price/`（筛选「分类：来自虎客」） | 微店预下单与常规报价单共用一张表，用分类区分 |
| 虎客好店佣金列表 | `/xcrm/contract/commission/` | 分销商、佣金、分销订单、订单回款、佣金比率、结算状态、付款记录 |
| 虎客名片访客消息 | `/sys/hookcard/` | 需先绑定微信到 CRM 用户；每次读取上限 200 条，读取后需一次处理完匹配，否则不再读取 |

说明：`/sys/hookmember/` 目录本身返回 403，仅 `shop` 子页可访问；未发现 `member`、`goods`、`order` 等其他子页（均为 404），可判断会员与订单没有独立管理页，统一并入 CRM 既有列表。

### 3.2 会员建档

```
微信用户进入小程序 → 成为虎客会员
        ↓（平台自动写入 CRM）
客户表：个人客户（type=1，cu_from=-1，无客户编号），客户名「姓名 手机号」
联系人表：姓名「虎客会员 + 16 位标识」，挂在该客户下
```

正式库现状：联系人表 15 条「虎客会员…」，对应客户 11 条建于 2019-04（归属 B1，名称仍为「虎客会员…」），2 条建于 2026-01-26（客户 15034「高小姐」归 M56、15035「肖婷姣 15952438657」归 M77，已被业务员改名并认领）。会员联系人的手机、微信、邮箱字段均为空。

### 3.3 下单与转订单

```
会员在小程序提交订单
        ↓
CRM 报价 / 预下单（price 表）：分类「来自虎客」，主题 = 虎客订单号 HM + 16 位
        ↓（业务员在 CRM 点「确认生成订单」）
CRM 订单（contract 表）
        ↓
发货单 / 出库单 / 计划回款 / 回款记录（现有链路）
```

预下单单据包含的字段（以 ID 214 为例）：主题（虎客订单号）、客户、分类「来自虎客」、币种与汇率、日期、总折扣、报价总额、不含税总金额、接收人（虎客会员标识）、明细（产品 ID、编号 / 条码、品名、单位、数量、单价、税率、金额）、**交付说明**（收货人、电话、地址以文本形式拼在一起）、分销商、虎客订单号、转成订单记录。

正式库 4 条预下单（2026-01-26，10.00 / 30.00 / 7.00 / 2.00 元）均为试单性质。其中 ID 214 于当日 11:18 由陈海云确认生成订单（ID 25501），该订单此后已从 CRM 删除（网页查 25501 返回「未发现」，镜像库同样没有），镜像与 CRM 在这一条上并无偏差。

## 4. OPEN API 能力边界

| 环节 | 接口 | 可用性 |
|---|---|---|
| 读取上架状态 | `api.output` · `dt=product` | 可用，返回 `hm_shop` 的展示文本（不上架 / 上架 / 精选）、`wxflag`、各电商编号 |
| 修改上架状态与售价 | `api.update` · `dt=product` | 售价 `price` 文档已列明可写；`hm_shop` **文档未列**，需在测试公司（ne2993）验证 |
| 读取预下单 | 无 | 文档 71 个接口中报价单只有写入（序号 20）与修改（序号 21），无读取接口 |
| 读取转化后订单 | `api.output` · `dt=contract` | 可用，已在现有同步链路中 |
| 会员（客户 / 联系人） | `api.output` · `dt=customer`（`extend=1` 含联系人） | 可用，会员即普通个人客户与联系人 |
| 佣金 | 无 | 未见对应接口；当前无数据 |

镜像库侧的差距：`sync/specs.py` 中 product 表未同步 `hm_shop`、`wxflag`、`ydh_sn` 等字段（原始 JSON 表 `raw_records` 里有完整内容，本文数据即由此取得）。

## 5. 对接方案建议

### 5.1 商品与价格上架自动化

1. 在测试公司验证 `api.update` 对 `hm_shop` 的写入（取值 0 / 1 / 2），同时验证 `price` 写入后产品读取接口的回显。
2. 验证通过：新增 `scripts/hm_shop.py`，支持「按型号或分类筛选 → 批量置上架 / 精选 → 写入售价 → 回读核对」，沿用现有写入策略（提交前查重、提交后回读）。
3. 验证不通过：脚本只产出待上架清单（.xlsx），上架动作在产品列表用批量编辑完成。
4. 镜像与前台：product 表补 `hm_shop`、`wxflag`、`intro`、`parameter`、`list_remark` 等列，`--rebuild --table product` 回填；产品页加「好店」列与筛选项，对「已上架且售价为 0」的产品给出提示。

**上线前需处理**：13 个上架品的售价为 0，且商品说明与技术参数基本为空。建议先确定小程序端价格与文案的实际表现，再决定是补齐售价还是调整上架范围。

### 5.2 微店订单纳入前台监控

预下单无读取接口，取数有三种方式，建议按 A → C 的顺序推进：

- **A（当前可行）**：以转化后的订单为准。在 `contract` 同步结果中识别微店来源（识别口径待定：预下单主题 `HM…` 是否带入订单、客户是否为虎客会员客户、或用订单自定义字段标记），前台展示已转化部分。
- **B（半自动）**：报价单列表支持导出，按约定周期导出后放入固定目录，由脚本入库，补上「未转化」部分。
- **C（需外部确认）**：向 XTools 询问报价 / 预下单是否有未公开的读取接口或后续计划。

前台新增「微店」页的内容建议：预下单列表（单号、会员、金额、明细、收货信息）、转化情况（已转 / 未转、转化用时）、未转化超时提醒（按天数分档）、上架商品与库存对照。

### 5.3 虎客会员客户治理

现有镜像数据即可完成，不依赖新接口：

1. 识别：联系人姓名以「虎客会员」开头的记录，取其客户 ID 集合。
2. 出清单：会员标识、对应客户、建档日期、所有者、是否有订单、手机号是否与既有客户重复。
3. 处理建议：11 条 2019 年的会员客户仍挂在 B1 名下且未改名，可判断为早期试用遗留，建议确认后统一处理；新增会员客户按手机号与既有客户比对，重复的合并，未重复的指派所有者并补联系方式。
4. 前台：客户页与联系人页增加「虎客会员」标识与筛选。

## 6. 待确认事项

1. `hm_shop` 能否经 `api.update` 写入（测试公司验证）。
2. 小程序端对 `price = 0` 的商品如何展示价格与下单入口。
3. 报价 / 预下单是否有读取接口或导出接口（需向 XTools 确认）。
4. 会员与客户的绑定是否依赖客户名或联系人名，MW 侧改名或合并客户是否影响后续会员下单的归属。
5. 店铺配置项（LOGO、背景图、咨询电话、邀约会员介绍文字）由谁补齐，以及是否启用分销佣金。
6. 微店订单的业务归属规则：接收人为虎客会员时订单归哪位业务员、是否计入业绩与提成。
